CITY-AS-MEMORY PASS (non-canonical-phase, additive UI/city/quality/input slice): a unified input abstraction (`src/input.ts`) now routes keyboard, mouse, touch, and standard-layout gamepad input through the same logical/rebindable actions, with real touch controls (movement joystick, look zone, contextual action cluster) and Pointer-Events-based input-mode detection (no user-agent sniffing). Versioned/migrated settings persistence (`src/settings.ts`) covers key bindings, camera sensitivity, haptics, and accessibility (reduced shake, reduced hit-flash); a manual quality-tier choice always overrides the automatic frame-budget governor (`src/quality.ts`, AUTO/LOW/MEDIUM/HIGH with hysteresis; touch input is never treated as a low-quality signal). The HUD now has explicit FULL/MINIMAL/CONTEXT_ALERT/hidden-exploration modes, and a world-space label replaces a former fixed prompt over the landmark. City density increased via `InstancedMesh` traffic (separate sedan/van/bus meshes bucketed deterministically for real vehicle-type variety, not one repeated box), pedestrians, and street detail; a new city fabric module (`src/city.ts`) adds district identity, parcel land use, a landmark with a stable id that can be damaged by shockwave impact and later rebuilt on century advance, and public-memory markers projected from real collapse events (the public account can diverge from the event, but the underlying objective `history.ts` event is never mutated to match it). Every public-memory marker now also spawns a small inspectable plaque mesh in the world at the event site (collapse, landmark damage, and archaeology-recovery corrective markers all included), and a rebuilt parcel that carries forward reused relic material gets a distinct octahedron lineage marker — both are genuinely instantiated world objects, not just aggregate counters, and both are bounded (oldest mesh disposed past a fixed cap) independently of the unbounded underlying save data. Century advance no longer instantly snaps a rebuilt parcel to full height: it grows from near-zero over ~3 seconds while easing its color toward its new land-use tint (a real, visible reconstruction beat). Buildings/rubble/scars are now spatially partitioned (`src/spatialGrid.ts`, uniform grid, `buildingGrid`) and every wall/grapple/shockwave query goes through it, so `activeChunkCount` reports the real occupied-cell count instead of a hardcoded placeholder. Rubble and terrain-scar meshes are capped (140 / 60) with oldest-first disposal (`scene.remove` + geometry/material `.dispose()`) so very long sessions cannot leak GPU resources; the objective `history.events` record and the save's `scars`/`city` blocks are never trimmed, only the decorative meshes are. The campaign save envelope was bumped to version 3 to carry the new city/landmark-structure state, with forward migration from v1/v2 saves, rejection of saves from a newer future version, and malformed-save recovery, all covered by `test:browser`. `render_game_to_text()` now also reports `inputMode`, `qualityMode`/`qualityTier`, `hudMode`, `cityEra`, `districtStates`, `landUseCounts`, `trafficCount`/`trafficVehicleTypes`/`pedestrianCount`/`streetActivityCount`, `activeChunkCount`, `cityDetailCount`, `landmarkStates`, `publicMemoryCount`, `materialLineageCount`, and `performance.frameBudgetState`. This pass does not itself complete Canonical Phase 2.

LAST VALIDATION: `npm run verify` passes (build + typecheck + 48 Vitest tests: 16 foundation + 32 expansion covering input/settings/quality/city/spatial-grid). `npm run test:browser` passes the full existing traversal/destruction/combat/history/deep-time journey plus legacy-save migration to v3, corrupt-save recovery, and rejection of a future save version, with zero console errors. `npm run test:performance` and `npm run test:browser:phase1` (its two constituent commands each independently confirmed this pass) run the four-scenario request-animation-frame baseline cleanly (zero console errors); this sandbox is CPU-constrained (2 vCPU, headless SwiftShader software rendering), so its absolute FPS numbers are not representative of a real GPU and are reported only as a stable relative before/after comparison, not as a device performance claim. A separate manual draw-call comparison (same scene, same viewport, 30 sampled frames after settle) found average draw calls essentially flat (~24 before this pass vs. ~25 after) despite the added InstancedMesh traffic/pedestrian/street-detail density, i.e. the added visual density did not proportionally increase draw calls. No physical device was used for any of this testing; mobile viewport/touch behavior was verified only via Chromium's built-in mobile emulation (Playwright `isMobile`/`hasTouch`), which is explicitly not equivalent to physical Android/iOS performance testing.
